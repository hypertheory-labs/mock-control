## Answered: The library works on MSW 3 unchanged
**Answer (measured):** held. The library builds against 3.0.3 with no source changes.
In fresh Angular 22 apps, one per version, following the README: both compile (3 only
after the start option is renamed), and in headless Chrome, three runs each, the mocked
endpoint answers with the mock, the pass-through reaches the real file, the log shows
`passthrough` and `ok 200`, and the panel renders.

I nearly wrote "disproved." My first harness waited for the store to exist, which happens
before `worker.start()` finishes, so requests raced the worker on both versions. MSW 2
happened to pass the first time and MSW 3 didn't. Waiting for Angular to bootstrap (which
the README's `main.ts` does only after the worker starts) fixed it for both. A failure
that only one version shows is still worth checking against the other.

Not measured on 3: the known limits (declined in the plan), failure and delay modes, and
held requests. Those paths don't touch anything MSW changed that I know of, which is a
reason, not a measurement.
